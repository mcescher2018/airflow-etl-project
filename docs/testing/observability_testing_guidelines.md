# Observability Testing Guidelines

This document explains how to inspect ETL results after the pipeline has executed, using Airflow’s UI and optional external tools such as Streamlit or Python scripts.  

Observability testing focuses on verifying run history, task behavior, and data outputs.

---

## 1. Airflow UI

Use the Airflow web interface to inspect the operational status of the ETL pipeline.

### 1.1 DAG Runs

From DAGs → <your_dag> → DAG Runs, verify:

- number of successful / failed runs  
- run timestamps and scheduling regularity  
- run duration  
- manual vs scheduled triggers  

Graph View and Tree View help confirm the execution path.

### 1.2 Task Instances

From DAGs → <your_etl_dag> → Graph View → click a task, inspect:

- task status (success, failed, skipped, retry)  
- execution time  
- retry count  
- upstream/downstream dependencies  
- logs (stdout, errors, warnings)  

Gantt View provides timing and parallelism insights.

---

## 2. KPI & Dashboard Tools

If Streamlit dashboards or Python scripts are available, use them to inspect ETL outputs.  

Typical checks include:

- daily or weekly KPIs  
- trend charts  
- anomalies or missing data  
- summary statistics  
- comparisons between runs  

These tools read directly from the data files or databases produced by the ETL pipeline.

---

## 3. Direct Data Inspection (Optional)

Depending on the storage backend (CSV, DuckDB, SQL), you may inspect data directly:

- open CSV files generated by the ETL  
- run DuckDB queries  
- check row counts and schema  
- verify timestamps and expected fields  

This step is optional and depends on available tools.

---

## 4. End‑to‑End Validation

Combine UI inspection and data checks to confirm:

- the DAG executed correctly  
- ETL outputs are present and valid  
- dashboards reflect updated data  
- notifications or emails were triggered  

This provides a complete view of pipeline health and output correctness.
